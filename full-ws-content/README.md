## The learner starts in an issue, not in the Actions tab

**New attendee setup:** every lab's review pack includes an Azure setup page with
complete instructions for entering your own tenant, subscription and existing
resource group, signing in when needed and verifying access. Open the
[Azure setup guide index](../README.md#fill-your-own-azure-values-and-sign-in).
No author's actual Azure values are supplied. Setup is not provisioning, and
full reviewed workload cleanup remains required for any authorized live exercise.

1. Choose a lab and make your own private copy from its public template.
2. Open **your copy's Exercise issue**, using the link AgentAlvine places in its README.
3. Read the current task in that issue body. Complete the real edits, commits,
   pushes, issue/PR work or independent review required by that activity.
4. Credential-free checks and AgentAlvine run from the corresponding GitHub
   events. AgentAlvine validates the observed work and updates **the same issue
   body**, showing completed activities, feedback and the next activity.
5. Use Actions to inspect results or diagnose a delay, not as the main course UI.

Public previews are **read-only instructor examples with zero learner progress**.
They are not bug reports and are not substitutes for a participant's issue.
The catalogue has no Exercise issue because it only lists the eight courses.
Do not tick progress manually, invent an approval or dispatch a cloud workflow
from a checkbox. GitHub progress is never Azure deployment authorization.
